# psyteardown AI Product Studio

> 用户带来的不必是完整产品设计，而是一个值得改变的现实；平台负责把它发展成经得起使用、验证和持续演化的真实产品。

psyteardown 正在从产品拆解与体验验证工具，发展为面向个人与企业的 **AI Product Studio（AI 产品生成与演化平台）**。

你不需要先写好 PRD，也不需要先成为产品经理、设计师和工程师。输入可以只是一个愿望、反复出现的困扰、商业目标、对现有产品的不满，或者一个推进到一半的项目。平台会承担大部分研究、方案搜索、设计、实现、测试和修复工作，并在真正需要价值判断、现实资源或不可逆授权时邀请你参与。

## 它最终交付什么

平台不会止步于报告、效果图或未经运行的代码，而会逐步形成：

1. 对目标、用户、情境、约束和成功标准的可纠正理解；
2. 多个具有真实差异的产品论点与实现路径；
3. 可以运行、体验和测量的产品；
4. 与关键声明绑定的证据、未知、风险和适用边界；
5. 可以部署、制造、执行或继续演化的交付物。

这里的“产品”不局限于 App。它可以是软件、硬件、服务、内容、工作流或组织流程，也可能是对现有工具的改造。平台忠于用户希望改变的结果，而不是忠于“必须生成某一种东西”。

## 用户如何使用

核心协作循环是：

```text
表达一个不完整想法
  → 平台展示“我目前怎样理解”
  → 用户纠正关键误解
  → 平台形成 Product Contract
  → AI 自主研究、生成、评审、测试和修复
  → 用户直接使用阶段性成果
  → 反馈进入下一轮迭代
  → 达到交付门槛，或诚实说明还缺什么
```

聊天是表达意图和发出指令的入口，但不会成为唯一界面。Product Studio 会长期保存成果、版本、证据和决定，而不是把项目状态埋在聊天记录里。

## Product Studio 的五个工作区

### 对话与指挥

表达目标、补充情境、纠正理解，并要求平台继续、暂停、回退、分叉或扩大探索。

### 产品契约

持续展示：为谁改变什么结果、什么才算成功、明确拒绝什么、有哪些成本和风险、哪些是事实、假设或未知。

### 产品工作台

直接运行和体验 AI 产生的软件、交互、内容、设计或工程成果，而不是只阅读它们的描述。

### 决策与待办

只呈现真正需要人参与的事项，并说明为什么需要决定、选择会改变什么、平台的建议和依据是什么。

### 证据与进度

展示哪些声明已验证、部分支持、被反驳或仍未知，以及当前版本能被称为什么、还不能声称什么。

## AI 做什么，人做什么

AI 默认负责：

- 从不完整表达中提取目标、矛盾、未知和隐含约束；
- 研究现有行为、竞品、替代方案和相关证据；
- 形成多个竞争性问题解释与产品路径；
- 制作界面、代码、内容、测试和交付材料；
- 在预算内执行生成、评审、构建、测试、修复和回归；
- 保存版本、来源、依赖、成本和审计记录；
- 主动暴露不确定性、风险和替代解释。

人负责或授权：

- 决定什么值得追求、哪些伤害不可接受；
- 提供 AI 无法获得的现实、组织和文化情境；
- 授权敏感数据、资金、外部系统和现实设备；
- 决定真正的价值冲突和不可逆选择；
- 对法规、安全、制造、质量和发布承担具名责任；
- 参与无法被仿真替代的真实使用验证。

目标不是让人参与得越少越好，而是让人的参与保持**最小必要、高信息量、责任清晰**。

## 不制造“看起来完成”的垃圾

以下情况不会被标记为产品已经完成：

- 只生成了 PRD、分析报告或静态效果图；
- 代码没有成功构建和运行；
- 自动测试不存在，或关键失败被忽略；
- 目标结果没有可观察的验证路径；
- 仿真结果被包装成真实的物理、行为或商业结果；
- 用户仍需自行整合大量互不兼容的输出；
- 已知的高风险未知被隐藏在乐观摘要里。

平台会明确区分 Concept、Runnable Prototype、Field Trial、Operational Candidate 和 Released Product。成熟度只说明当前真正达到的交付层级，不是营销标签。

## 第一条完整纵向切片

当前优先验证数字产品路径：

```text
模糊目标
  → Product Intent
  → Problem Model
  → Outcome Contract
  → 2–3 个 Product Thesis
  → 可运行 Web 产品
  → 自动构建、浏览器测试和失败修复
  → 用户直接体验并反馈
  → 可导出或部署的交付包
```

首条切片暂不同时解决原生移动应用、通用硬件制造、复杂企业权限、无限自治或无人批准部署。

项目仍在开发中。

- 已有一套可追溯的产品拆解、体验假设、设计反馈、证据和工程验证内核；

- Product Studio Web 工作空间、产品生成沙箱和完整交付闭环尚未完成；
- 当前任何仿真、渲染和自动测试都不会被当作真实用户或现实世界结果。
