Flowith 是一款以「无限画布」替代聊天框的 AI 工作空间(AI Agent 操作系统),核心机制:
1. 画布式交互(Context Playground):不使用线性聊天框,而是二维画布。每一次提问、每一个模型回复、每一张生成图片都是一个可拖动的节点,节点之间可连线、分叉、并排比较;同一画布内可同时调用多个不同 AI 模型;
2. 多线程分叉:从任意一个已有节点向下继续追问,形成分支,不同分支各自继承上游节点作为上下文,历史分支保持可见、可回溯,不会被新对话覆盖;
3. Agent 模式(Agent Neo):开启后由 Agent 自主做任务规划、执行与重新规划(re-planning),处理多步骤长任务,过程与中间产物直接铺在画布上;
4. 知识花园(Knowledge Garden):用户上传自己的文件资料,系统将文档拆解为「知识条目」,在 Agent 执行任务时自动匹配相关内容并转成「种子」(seeds)片段注入上下文,定位为用户的长期记忆;
5. 知识变现:知识花园可被创作者打包出售,平台设有知识市场(Knowledge Marketbase),别人可订阅或购买;
6. 积分计费:免费版给一次性积分额度,付费分为多个订阅档位,不同操作(文本、图像、视频生成)消耗不同积分,积分不跨周期累计结转;
7. 画布协作(Canvas Cowork):可把外部 AI 编码 Agent 的输出接入同一画布,作为共享的可视化协作空间;
8. 官方宣传语包括「我们杀死了聊天框,因为人的思维不是直线发生的」以及以 GAIA 基准成绩作为 Agent 能力背书;
9. 官方对早期宣传口径做过收回:官方博客明确写道「无限步骤」「数百万 token」等旧说法不应被当作当前产品规格。
关键触点:空白画布首屏、节点分叉操作、Agent 任务执行过程展示、知识花园上传与匹配、积分余额与消耗提示、付费墙与订阅档位选择页、知识市场浏览页。
用户动机:处理需要保留多个并行方案的非线性工作(研究、写作、比稿)+ 对「不想再滚动翻找聊天记录」的真实痛点 + 对「拥有一个持续变聪明的私人 AI」的期待;也存在把画布铺满节点后自己也找不到主线、以及为省积分而不敢多试的行为。
