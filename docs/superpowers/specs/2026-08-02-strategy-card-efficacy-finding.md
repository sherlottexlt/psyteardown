# 策略卡效力边界:约束型有效,发现型无效

- 日期:2026-08-02
- 状态:**实证发现 + 改进提案,未评审**(不是已确认的 v7 计划)
- 依赖:v4 程序性记忆(策略卡)、v5 自评。本文档不改动任何已合并行为。

---

## 1. 一句话结论

策略卡目前**只能约束模型已经在做的事,不能让模型开始做它原本没想到的事**。前者实测生效,后者实测完全落空。

---

## 2. 实证来源

2026-08-02 对《金铲铲之战》连续两次拆解(同一输入、同一模型 deepseek-v4-flash、同一案例库)。

v1 拆解的自评(score 0.62)提出三条缺陷,据此蒸馏并批准三张策略卡,v2 带卡重跑:

| 策略卡 | target_step | 类型 | 结果 |
|--------|-------------|------|------|
| `flag-speculative-mechanism-mapping` | mapping | 约束型(限制置信上限 + 强制标注) | ✅ **生效** |
| `detect-social-proof-clues` | mapping | 发现型(要求新增原本缺失的映射) | ❌ **完全落空** |
| `separate-peak-valence` | assessment | 发现型(要求新增情绪方向标注维度) | ❌ **落空** |

### 生效的证据(约束型)

- 全文出现 10 处"推测"标注,v1 为 0 处
- 两条映射被打上 `⚠️低置信`(0.45 / 0.40)
- v1 中证据最薄弱的 `海克斯三选一弹窗→cognitive-biases·anchoring`(0.62)被**整条移除**
- `经济与利息系统→anchoring` 置信度 0.80 → 0.73

### 落空的证据(发现型)

- v2 全文**零条** `cialdini-influence·社会认同` 或 `cognitive-biases·从众效应` 映射
- 输入中"强势阵容 T0/T1 榜单与攻略生态发达,玩家常抄阵容"的证据依旧只被映射到 `loss-aversion-trigger` 与 `dynamic-comparison`
- 峰值映射仍未标注情绪正负,扣血结算(负向)与三星特效(正向)仍混同处理

### 已排除的干扰项:不是注入 bug

直接对 `select_for()` 做了实测,确认两张 mapping 卡的规则原文**逐字进入了 step3 的 prompt**:

```
=== mapping 步实际注入 ===
- 当证据出现榜单、排行、攻略生态、大众流行选择、'别人都在用/都在抄'时,必须优先考虑社会认同与从众效应,不要一律归入进展所有权。
- 仅凭界面布局、控件位置、视觉层级推测的心理机制,置信度不得超过0.5,...
```

同时确认 `prefer-loss-aversion-over-investment`(`applies_to=['教育App','社交裂变产品']`)被正确排除,`_applies` 过滤逻辑正常。

**注入链路完全正常,失败发生在模型遵循环节。**

---

## 3. 机理假设

step3 的映射是**逐功能/逐触点**推进的:模型先锁定一个功能,再从框架库里挑原则。策略卡作为全局附加约束,在"已选定候选原则、正在打分/写证据"这一刻是可执行的(减法);但要让模型在**候选生成阶段**多想出一条它没联想到的原则,一句散在 prompt 里的规则拿不到足够权重——它不在模型当前的注意力焦点上。

简言之:**约束作用于输出的过滤阶段,发现需要作用于候选的生成阶段,而现在两者注入在同一个位置。**

---

## 4. 改进提案(未实现)

核心思路:把发现型规则从"附加约束"改为"独立前置步骤",让线索扫描成为一次单独的、必须产出列表的模型调用。

- **新增 step 3.0「线索扫描」**:在逐功能映射之前,先用框架库中所有原则的 `look_for` 线索,对产品描述做一次全量扫描,强制输出"命中线索 → 候选原则"的清单。发现型策略卡注入到这一步。
- step3 的映射改为**在该清单基础上做取舍**,而非从零联想;清单中被丢弃的候选需给出理由。
- 策略卡 schema 增加 `card_type: constraint | discovery` 字段,由 `reflect` 蒸馏时判定,`select_for` 按类型分发到 3.0 或 3。

预期代价:多一次 LLM 调用;`look_for` 线索质量成为新瓶颈。

### 明确不做

- 不在本提案中改 step3 的映射逻辑本身
- 不做策略卡自动生效性回测(需要先有 A/B 跑批基础设施)
- 不引入策略卡权重/优先级排序(先验证类型二分是否够用)

## 5. 附带发现:输入准确度是质量天花板

同一组实验中,v2 **凭空编造**了"SSR 保底""保底次数不因卡池切换重置",而金铲铲的棋子获取根本没有保底机制,也没有 SSR 稀有度分级。v1 未出现该错误。

模型会为缺失的机制细节自行脑补填空,且自评能抓到一部分(v2 自评确实指出了这条)但不保证抓全。

建议:产品描述模板增加**「事实边界」段落**,显式声明"本描述未提供的界面文案/数值/动画细节一律不得作为证据引用",并对易被脑补的机制(保底、体力恢复、付费续命)做定向否认。该做法已在 v3 输入中试用。

---

## 6. v3 验证结果(2026-08-02 当日回填)

同输入模板改造 + 框架库 5→7 后重跑,结论如下。

### 已验证成立

- **「事实边界」段落有效**:v3 全文零处 SSR/保底/体力/复活类脑补证据(v2 有多处)。定向否认易脑补机制这一手法可复用。
- **发现型缺口靠改输入结构可修复,靠策略卡不可**:把"攻略生态与阵容榜单"从埋在赛季轮换条目里提升为**独立功能条**后,`cialdini-influence·social_proof` 立刻出现 3 条映射、置信 0.90。而同一条规则以策略卡形式注入时(v2)产出为零。这正面印证了第 2、3 节的结论——**发现型规则需要作用于候选生成阶段,给它一个独立的结构位比给它一句约束有效得多。**

### 已证伪 / 出现预期外结果

- **新框架不会被自动采用**:`near-goal-persistence` 入库后使用数为 **0**,尽管输入中已写入"接近晋级线时就差几分上分的冲刺感"。仅仅把框架放进库里并不足以让 step3 联想到它——这与发现型策略卡失效是同一个机理。
- **框架是"替换"而非"累加"**:`cyclical-ownership-reset` 用了 11 次,同时 `dynamic-social-competition`(v1/v2 的主力框架,段位/排名映射的主要归属)在 v3 **完全消失**。新框架挤占了旧框架的映射位,而非补充。原先预期的"重复映射恶化"未出现,实际风险是**语义相近的新框架会吞并旧框架的地盘**,导致跨版本报告不可比。

### 新发现:自评分不具区分度

| | v1 | v2 | v3 |
|---|---|---|---|
| 自评分 | 0.62 | 0.62 | 0.62 |
| 映射条数 | 39 | 33 | 41 |
| 脑补性证据 | 有 | 更多 | 无 |
| social_proof | 无 | 无 | 3 条 |

三份内容差异显著的报告拿到**完全相同**的分数。自评器每次都能找出 5-6 条缺陷并给出相近总分,说明 `score` 反映的是"自评器倾向于挑出多少问题",而非报告的实际质量。**不应把 v5 的 score 当作跨版本质量指标或优化目标**——这与 v5 设计文档中"按 score 自动筛选/降权低质案例"的后置设想直接相关,该设想在当前实现下不可行。

### 遗留的真实缺口

v3 自评指出的头号漏拆是**可变比率强化(variable-ratio reinforcement)**——商店刷新与开蛋的核心成瘾机制。核查确认该机制在当前 7 个框架中确实没有独立归属(`hook-model` 的多变奖励只覆盖"奖励不可预知",不覆盖"强化程序与行为频率的关系")。这是比沉没成本更关键的缺口,且 `learn` 从现有 6 个案例中未能提炼出它。
