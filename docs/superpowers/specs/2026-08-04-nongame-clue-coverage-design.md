## 1. 背景

v7 把检索改为 IDF 加权词元重叠后,游戏类产品效果显著。但 v7 合并前评审记录了一条限制:「关键词与全部框架无交集时退回字母序,实测记账 App 非零 0/8」。

### 更正:那条限制的数据是错的

该测试用的画像只有 **3 个关键词**(`记账App / 每日提醒 / 账单分类`)。而 step1 产出的真实画像有 **12~19 个关键词**(实测 6 个既有案例:小红书 12、多邻国 12、拼多多 13、Keep 13、王者荣耀 13、金铲铲 19)。

按真实丰度(12 词)重测:

| 画像 | 非零框架数 | 头名 | 语义判定 |
|------|-----------|------|---------|
| 记账 App | **6 / 8** | `fogg-behavior-model` 5.43 | ✓ 习惯行为 + 一键记账降摩擦 |
| 待办清单 App | **5 / 8** | `flow` 12.48 | ✓ 专注计时器/沉浸 |
| 冥想睡眠 App | **6 / 8** | `cognitive-biases` 5.55 | ✗ 认知偏误领衔冥想 App 不成立 |

**所以"零覆盖"是稀疏画像造成的假象,v7 第 11 节该条须按上表重写。** 真实存在的问题不是覆盖率,而是**健康类的头名不正确**。

## 2. 真实根因:词汇层级错位,非品类缺失

`self-determination-theory` 在冥想画像上得 **0.0**,但语义上句句对应:

| 画像关键词 | SDT 原则 | 现有线索 | 是否命中 |
|-----------|---------|---------|---------|
| 正念课程逐级解锁 | competence | 难度梯度 / 技能提升曲线 | ✗ 无共享词元 |
| 好友一起冥想 | relatedness | 社区 / 协作 / 互助 | ✗ |
| 呼吸引导音频 | autonomy | 可自定义 / 可跳过 | ✗ |

而 `cognitive-biases` 夺魁靠三个零碎命中:`连续`、`打卡`(均来自线索「连续打卡中断警告」)、`订阅`(来自「默认订阅」)——正是 v7 一路在打的"单个通用词元"浅层假阳性。

**结论:线索写成了设计师术语(难度梯度、非强制路径),而产品画像说的是用户可见的表层话(课程解锁、好友、跳过)。** 字符 n-gram 无法跨越这种词汇层级差,也无法跨越同义词。

## 3. 目标与非目标

### 成功标准

1. 三个验证画像的**头名框架语义正确**,由测试锁定。
2. 现有 6 个案例的头名框架**一个都不改变**。
3. 抽卡回归测试继续通过。
4. IDF 稀释可控:新增线索不得把关键区分词的权重压到伤害排序。

### 明确不做(YAGNI)

- 不改 `Framework` schema(不引入同义词分组结构)——`_pool` 只取词元并集,分组对检索无任何影响
- 不改检索算法(`_tokens`/`_pool`/`_idf`/`_score`/`retrieve_frameworks` 全部不动)
- 不覆盖金融/理财与 B 端 SaaS 品类
- 不新增框架——现有 8 个种子框架足以解释这两个品类,缺的是线索词汇
- 不改字母序补齐行为(那是 v7 另一条独立限制)

## 4. 方案

**以验证画像驱动,倒过来做:先写画像与期望头名,再补最小必要线索。** 这样避免凭空发明线索,也避免过度添加导致稀释。

### 验证画像(各 12 词,匹配真实丰度)

| 画像 | 期望头名 | 当前状态 |
|------|---------|---------|
| 记账 App | `fogg-behavior-model` | 已正确 → 防回归锁 |
| 待办清单 App | `flow` | 已正确 → 防回归锁 |
| 冥想睡眠 App | `self-determination-theory` | **0.0 分,本次要修** |

只做 3 个:第 4 个候选(睡眠追踪)的期望头名难以人工判定,纳入会使"头名语义正确"这条标准变软。

### 改动:`self-determination-theory` 的 `look_for`

保留原抽象词,**并列补入表层同义变体**:

| 原则 | 现有线索 | 增补 |
|------|---------|------|
| autonomy | 可自定义 / 可跳过 / 非强制路径 | 自选内容、跳过引导、免打扰、自定义时长 |
| competence | 难度梯度 / 即时反馈 / 技能提升曲线 | 课程解锁、逐级进阶、关卡、完成率、时长统计 |
| relatedness | 社区 / 协作 / 互助 / 关系绑定 | 好友、一起、同伴、组队、分享给朋友 |

其他框架**仅在验证不达标时才动**,遵循最小必要。

## 5. 稀释风险与护栏

新增线索会扩大 SDT 的词元池,抬高部分词元的 `df`,从而压低其 IDF 权重。v7 已实测该库 `df` 上限仅为 3(N=8),权重区间 2.079~0.981,本就不宽——**再压缩会削弱区分力**。

故实现时须测量并记录:

- 新增线索后全库 `df` 分布的变化
- 现有 6 案例头名是否改变(硬性:不得改变)
- 抽卡回归测试(硬性:必须通过)

若某条增补线索使既有案例头名翻转,该线索应被收回而非调整期望值。

## 6. 测试策略

新增 `tests/kb/test_retrieval_coverage.py`,离线确定性,只用 `load_frameworks()`(种子库,不依赖 gitignore 的 `.field-test/store/`)。

三个画像各一条测试,断言 `retrieve_frameworks(...)[0].id == 期望头名`。使用 `min_n=0` 关闭补齐,使断言纯粹反映打分——这是 v7 回归测试踩过的坑(否则断言可能被字母序补齐"满足")。

既有 `tests/kb/test_retriever.py` 的 36 个测试与 `test_seed_frameworks.py` 的 schema 校验不得回归。当前基线 `228 passed, 2 skipped`。

## 7. 附带修正

v7 spec `2026-08-03-v7-framework-retrieval-design.md` 第 11 节第一条限制按本文第 1 节的实测数据重写,并注明原数据取自 3 关键词的稀疏画像、不具代表性。

## 8. 实际收敛结果(实现后回填,与 §4 原案有出入)

§4 原本计划给三条原则各补 4~5 条表层线索(共 14 条)。**实际只落地 3 条,全部在
`autonomy`:`跳过引导`、`免打扰`、`自定义时长`。** 收敛过程:

| 轮次 | 线索数 | 被否原因 |
|------|--------|---------|
| 原案 | 14 | `课程解锁` 引入词元 `课程`,直接翻转多邻国与 Keep 两个存档案例 |
| 二轮 | 9 → 8 | 逐条剔除:无验证画像命中者(`自选内容`/`逐级进阶`/`关卡`),只在 SDT 不该领衔的画像上加分者(`组队`/`分享给朋友`/`完成率`) |
| 三轮 | 8 → **3** | 扰动护栏:8 条版本在 16 个合理改写扰动中翻转 7 个 |

**根因:`好友`/`一起`/`同伴` 各自就是一个词元,df=1 拿满 IDF(2.079),而它们在真实
产品语言里极常见。** 王者荣耀的存档画像本就含「组队开黑与亲密关系」,多邻国本就含
「家庭套餐与好友动态」——只差一个同义词就翻。最刺眼的一例:

    王者荣耀 + 好友一起开黑  cialdini-influence → self-determination-theory

一个靠抽卡牟利的 MOBA 被 SDT(其 `ethics_notes` 自我定位为「健康的内在动机设计」)
领衔,工具的核心判断被反转。

**把线索写长不能降低风险。** 打分看共享**词元**,不看线索字符串长度:把 `同伴` 写成
`同伴陪伴`,共享的仍是 `同伴` 这一个词元,权重分毫不变。唯一有效的办法是让这些词元
根本不进入词元池。故 `relatedness` 与 `competence` 一条未补,冥想画像是靠**自主性
单档**通过的(SDT 11.09,第二名 `cognitive-biases` 5.545)。

最终实测:全库词元 403 → **408**,df 直方图 `{1: 373, 2: 24, 3: 6}` → `{1: 377,
2: 25, 3: 6}`,IDF 区间 0.981~2.079 **逐位不变**。稀释未发生(§3 标准 4 达成)。

### 对 §3「现有 6 个案例头名一个都不改变」这条护栏的修正

该护栏拿**冻结的措辞**在比,不足以保证稳定性:多邻国头名领先仅 1.39,一个含 `好友`
的关键词值 2.08。8 条版本完全通过了这条护栏,却在改写下翻转 7 处。已由
`tests/kb/test_retrieval_perturbation.py` 补强为「加一个合理改写词后仍不翻转」,
并显式登记一处基线既有的翻转(王者荣耀 + `新手引导可跳过`,命中 SDT 的**原有**线索
`可跳过`)作为已知例外——那是 v7 遗留问题,修它要动框架间相对权重,超出本次范围。

另记一条**未采纳的反对意见**:多邻国是 SDT 的教科书案例,Keep 由 SDT 领衔也比
`cognitive-biases` 站得住。该护栏把修复前的头名当成了基准真值,而那些头名恰是本次
要修的浅层匹配产出的。本次仍按已批准标准执行(它能防止无约束漂移),但该护栏本身
是否合理值得单独讨论。

### 两条方法论教训

**一、用照着线索表手写的薄画像下结论,会得出错误结论。** 回滚 8 条版本的过程中,曾用
自己照着 SDT 线索写的 6 词画像测出「SDT 成了万能吸铁石,其余 7 个框架在真实产品语言
上一律 0 分」,并据此把问题定性为全库性崩盘。换成按存档案例风格写的 12~14 词真实画像
重测,8 条线索对抖音/直播打赏/MOBA 三个画像**什么都没改变**(头名与非零数全同,均为
6/8)。其余框架的线索(`推送通知`/`红点`/`限时`/`倒计时`/`划线原价`/`热门榜`)本来
就是表层词汇。**下结论前,画像必须按真实丰度写,且不得照着线索表编。**

**二、"验证通过"要先确认验证跑在正确的对象上。** 本任务出现过三次空洞验证:(1) 读
案例 JSON 时路径写错,提取到 0 个关键词,却报告「6 个案例头名零翻转」;(2) 用当前
知识库去校验一条关于**未来**线索集的不变量,库里根本没有那些线索,自然零违反;
(3) 断言「任一关键词与任一线索至多共享 1 个词元」,实测有 3 处违反,且该规则对
两字线索被原样包含的情形在结构上无效。三次都是"跑了、绿了、于是相信了"。

## 9. 遗留

- `relatedness` 与 `competence` 的表层词汇覆盖仍是空白,冥想画像靠单档通过
- 其余 7 个框架的线索未做表层词汇审视(但实测它们本就多为表层词,优先级不高)
- `variable-ratio-reinforcement` 的线索是长句风格(156 词元),与其余 7 个框架的
  短词风格(28~58 词元)不一致;`_score` 是无归一化求和,池大的框架天然占优
- 王者荣耀 + `新手引导可跳过` 的基线翻转未修
- 本次**未**跑真实 LLM 端到端拆解,只验证了检索层头名

## 10. 端到端验证结果:本次改动在真实输入上**没有奏效**

2026-08-05 用真实 LLM(deepseek-v4-flash)拆解了一款正念类 App(潮汐),
输入 `.field-test/products/chaoxi.txt` 刻意**不含** SDT 的任何新线索词
(无「免打扰」「自定义时长」「跳过引导」),事实边界还明令禁止假设存在社交功能。

### 结果:SDT 没有进入检索结果

step1 产出 17 个关键词,step2 在 12 个框架里给 SDT 排**第 11**,得分 1.79:

| 排名 | 框架 | 分数 |
|------|------|------|
| 1 | `cumulative-progress-retrieval` | 8.80 |
| 2 | `flow` | 7.45 |
| … | | |
| 11 | **`self-determination-theory`** | **1.79** |

而那 1.79 分的**唯一**来源是词元 `引导`,来自关键词「呼吸引导」命中线索「跳过引导」
——正是测试注释里已登记的同形异义噪声(引导音频 vs 引导流程)。**本次新增的三条
线索在真实输入上贡献为零。**

### 自评独立指出了同一个缺口

未经任何提示,step5 自评写道:

> 疑似漏拆「自主感/选择自由」相关机制:正念类App常通过「自定义时长、自由选择声音」
> 等增强用户自主性,但拆解中未提及 self-determination theory 或类似框架。

建议栏直接点名「引入自我决定理论(SDT)的自主、胜任、连接维度」。这与 v3/v4 自评
反复点名 `variable-ratio-reinforcement` 缺席的情形完全同构。

### 根因:验证画像终究是我自己写的

对照两者的措辞:

| 我写的验证画像 | 真实 step1 产出 |
|---------------|----------------|
| 引导语可随时跳过 | 呼吸引导 |
| 夜间免打扰 | 睡眠模块 |
| 每周冥想时长回顾 | 专注计时 / 数据统计 |
| 正念练习分阶解锁 | 冥想课程 |

前后经历了三轮评审、扰动护栏、穷举鲁棒性检验,把「画像不得抄线索」的纪律做到了
很细——但**始终没有解决"画像由我构造"这一根本问题**。测试注释里那句「这三条测试
锁的是这三个画像 × 这些线索,不是检索已能处理这些品类」是对的,而且比我当时以为的
更致命。

### 换向量检索也不解决

用 ollama `bge-m3:567m` 对同一真实画像重排(框架文档 = 名称+摘要+tags+全部线索):

    hook-model 0.5604 / flow 0.5585 / … / self-determination-theory 0.4890(第 8,垫底)

相似度全域只有 0.489~0.560、跨度 7 个点。**向量检索把 SDT 排得和 bigram 一样靠后。**
故 v7 spec 里"将来换向量检索"这条预留,至少在这种朴素编码方式下不解决本问题。

### 推测的真正原因

其余框架的线索是**具体 UI 形态**(推送通知、划线原价、倒计时、红点),产品画像里
也确实会出现这些词,所以匹配得上。而 SDT 的构念是**心理状态**(自主、胜任、归属),
它由哪些界面特征满足是一个**解释判断**——那恰是 step3 这个 LLM 干的活,不是检索
能干的活。「呼吸引导」是不是自主性支持?需要推理,不是词汇匹配。

**这意味着:对构念抽象型框架,基于特征关键词的检索可能是错误的机制本身。**

### 结论

本次落地的 3 条线索让一个人造画像转绿,但没能让真实正念类产品检索到 SDT。
第 3 节的成功标准 1 在**测试意义上**达成,在**产品意义上**未达成。

现已有一份真实的正念类画像(案例 `803b9a231399f660`),后续任何修法都应以它、
而非人造画像作为验证对象。
