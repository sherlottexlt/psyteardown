# grill-me 实现边界：第 201–428 项

## 目的

用户已完成第 1–200 项的实现。后续实现应覆盖已经确认、且在当前决策树中形成闭合边界的第 201–428 项；实现完成后再继续追问第 429 项及以后，避免代码实现反过来影响尚未讨论的决策。

## 明确边界

### 可以实现

- 第 201–428 项对应的已确认领域模型、状态、revision、lineage、证据、审阅、隔离、撤销、仲裁、canary、污染传播和 clean rerun 基础设施。
- 相关 SQLite/repository、不可变快照、审计事件、依赖图、状态投影和测试。
- 对第 429 项所需的原始事实记录能力，例如保存 clean rerun 前后的排序 diff、选择机会集、人工选择记录和血缘引用；这些只能作为待审数据，不要提前定义第 429 项的最终资格结论。

### 必须停止

- 不实现第 429 项及之后的最终业务规则。
- 不自动实现“clean rerun 改变候选排序就切断旧选择流程支持”的判定；只能保存差异并标记待审。
- 不实现任何依赖第 429 项答案的资格继承、selection lineage invalidation、旧实验重绑定或自动恢复逻辑。
- 不通过代码结构暗示第 429 项的推荐答案已经被接受。

## 为什么停在 428

第 201–428 项可以组成一个相对闭合的实现层：

1. 201–350：核心领域、实验、证据、启发式和选择流程基础设施；
2. 351–399：执行者等价、独立性、依赖图、仲裁和审阅完整性；
3. 400–428：关键 canary、暂停/恢复授权、撤销收敛、未授权输出隔离、污染血缘和 clean rerun。

第 429 项开始处理 clean rerun 对候选排序、选择机会集和旧支持链的影响。这不是 428 的纯实现延伸，而是新的选择血缘治理分支；必须先继续 grill-me、取得用户确认，再实现。

## 新对话启动指令

新对话应先阅读：

1. 本文件；
2. [`CONTEXT.md`](../../CONTEXT.md)；
3. `docs/adr/0201`–`docs/adr/0428`；
4. 现有 `src/psyteardown/experience/` 和 `tests/experience/`。

然后按第 201–428 项实现和测试，优先保持不可变 revision、数据血缘和状态隔离；完成后报告测试结果，不要继续提问第 429 项，除非用户明确要求恢复 grill-me。

## 完成后的继续顺序

实现完成后：

1. 汇报第 201–428 项的实现范围、未实现的第 429+ 语义和测试结果；
2. 恢复 grill-me；
3. 从第 429 项开始，一次只问一个问题；
4. 用户确认第 429 项后，再决定是否创建 ADR 0429 和对应实现。
